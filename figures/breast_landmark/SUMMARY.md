# Breast Cancer DFS Landmark — 실험 정리

**기간** 2026-09-01 ~ 09-02 | **확정** T=24 (2026-09-02, 교수님 승인)

---

## 1. 결론: T=24로 가는 이유

### 1-1. 지표값 때문이 아니다 (중요)

AUPRC 절대값은 4개 코호트 전부 T=24가 높다. 하지만 **AUPRC의 baseline이 양성비율 그 자체**이고,
T=24는 landmark를 늘린 결과 양성비가 2~3배가 된 상태다. 즉 AUPRC 상승분에 prevalence 효과가 섞여 있다.

baseline 대비 lift(= AUPRC / 양성비율)로 정규화하면 **4개 코호트 전부 T=12가 높다.**
5개 모델 전부로 확장해도 마찬가지로, **코호트×모델 20쌍 중 18쌍에서 T=12가 우세**하다
(예외는 C1 MLP 2.04 vs 2.16, C4 RF 1.69 vs 1.86 두 개뿐).

| 코호트 | T=12 양성비 → AUPRC(LR) → lift | T=24 양성비 → AUPRC(LR) → lift | lift 승자 |
|---|---|---|---|
| C1 | 1.3% → 0.086 → **6.76x** | 3.9% → 0.104 → 2.69x | T=12 |
| C2 | 1.8% → 0.208 → **11.85x** | 9.6% → 0.300 → 3.12x | T=12 |
| C3 | 2.9% → 0.117 → **4.03x** | 7.7% → 0.221 → 2.85x | T=12 |
| C4 | 5.7% → 0.170 → **3.01x** | 16.4% → 0.324 → 1.98x | T=12 |

AUROC로 봐도 마찬가지다. C2(0.877 → 0.717)와 C3(0.796 → 0.754)는 오히려 T=12가 높다.

→ **"AUPRC가 높으니 T=24"는 방어되지 않는 논리다.** prevalence에 의존하는 지표를
서로 다른 prevalence 사이에서 비교하면 안 된다.

### 1-2. 진짜 이유: 추정 안정성

T=12는 성능이 나쁜 게 아니라 **측정이 안 되는** 상태다. test 양성이 코호트당 3~10명뿐이다.

| 근거 | T=12 | T=24 | 변화 |
|---|---|---|---|
| test 양성 수 (C1/C2/C3/C4) | 10 / 3 / 9 / 8 | 28 / 8 / 25 / 24 | 2.7~2.8배 |
| AUROC seed std (5 seed, 5 모델 평균) | 0.076 | 0.047 | 38% 감소 |
| F1 = 0 인 run 수 | **38 / 600** | **6 / 600** | 6.3배 감소 |
| recall 최소 해상도 (C2) | 0.333 (4단계) | 0.125 (9단계) | — |
| 코호트 간 AUROC 산포 (LR) | 0.657~0.877 (폭 0.22) | 0.696~0.754 (폭 0.058) | 4배 축소 |

C2의 recall이 0 / 0.333 / 0.667 / 1 네 값만 가질 수 있다는 게 T=12의 상태를 요약한다.
양성 한 명이 threshold를 넘고 못 넘고에 지표가 통째로 흔들린다.

### 1-3. 비용과 그 판단

T=24의 유일한 실질 비용은 **C2의 표본 절반 손실 (853 → 438, -49%)** 이다.
다른 3개 코호트는 거의 손실이 없다 (C1 3788→3646, C3 1619→1602, C4 741→739).

교수님 판단 (2026-09-02): 샘플은 줄지만 양성비율이 좋아지고, **샘플이 적은 상황 자체가
ProtoLLM에게는 유리한 무대**다. C2도 버리지 않고 유지한다. HP 튜닝은 대략적 성능만 보면 되므로 최소로.

## 2. 실험 설계

**데이터** `trial_1` (코드북이 텍스트로 디코딩된 버전) 기준, 4개 adjuvant 유방암 코호트.

| 코호트 | Trial | T=12 (n / 양성 / 양성비) | T=24 (n / 양성 / 양성비) | Feature (Cat/Num) | Missing |
|---|---|---|---|---|---|
| C1 | NCT00041119 | 3788 / 48 / 1.3% | 3646 / 141 / 3.9% | 23 (23/0) | 13.8% |
| C2 | NCT00174655 | 853 / 15 / 1.8% | 438 / 42 / 9.6% | 23 (19/4) | 11.5% |
| C3 | NCT00312208 | 1619 / 47 / 2.9% | 1602 / 124 / 7.7% | 16 (12/4) | 8.6% |
| C4 | NCT00688740 | 741 / 42 / 5.7% | 739 / 121 / 16.4% | 10 (7/3) | 0.6% |

**Landmark 이진화** `pos = (event==1) & (t <= T)`, `neg = (t >= T) & ~pos`, 나머지(T 이전 censoring)는 제거.
T 시점의 상태를 알 수 없는 환자를 음성으로 넣지 않기 위함.

**Split** `train_test_split(test_size=0.2, stratify=y)`. valid set 없음.
HP는 train 내부 K-fold CV로 탐색 (scoring = `average_precision`, 즉 AUPRC 기준).
CV도 stratified (sklearn이 classifier에 대해 자동으로 StratifiedKFold 사용, CatBoost는 명시적).

**규모** 8 데이터셋 × 5 모델(LR/XGB/MLP/RF/CAT) × 6 shot(4/8/16/32/64/full) × 5 seed(42/44/46/48/50)
= **240 run, 7200 지표 셀. 실패 0건.** GPU 6장(0,1,3,4,5,6) 작업 큐 분산, 총 98분.

**클래스 불균형 처리** `--balance balanced`
LR/RF `class_weight='balanced'` · XGB `scale_pos_weight` · CatBoost `auto_class_weights='Balanced'` ·
MLP `BCEWithLogitsLoss(pos_weight=n_neg/n_pos)`

## 3. T=12 경향

**AUROC 자체는 나쁘지 않다.** C2 0.877(LR), C3 0.796(LR) 등 오히려 T=24보다 높은 코호트가 있다.
문제는 그 값을 믿을 수 없다는 것이다.

- **seed 편차가 크다.** AUROC std 평균 0.076. C2는 0.100.
- **F1이 자주 0이 된다.** 600 run 중 38개. C2에만 19개가 몰려 있다.
- **지표 해상도가 거칠다.** C2는 test 양성이 3명이라 recall이 4개 값만 가진다.
- **코호트 간 AUROC 산포가 크다** (0.657~0.877). 이 폭의 상당 부분이 실제 난이도 차이가 아니라 표본 노이즈다.
- AUPRC lift는 높지만 (최대 11.85x) baseline이 1.3~5.7%로 워낙 낮아서 나오는 값이다.

**C2가 가장 심각하다.** train 양성 12명, test 양성 3명. 이 규모에서는 모델 비교 자체가 성립하지 않는다.

## 4. T=24 경향

- **모델 순위가 안정된다.** LR이 AUROC 기준 8개 중 5개, AUPRC 기준 8개 중 5개에서 1등.
  XGBoost는 평균 4.88등(AUROC) / 4.75등(AUPRC)으로 사실상 최하위.
- **코호트 간 AUROC가 0.68~0.75로 수렴한다.** T=12의 0.22 폭이 0.058로 줄었다.
- **few-shot 곡선이 단조 증가하고 full이 천장이다.** shot이 늘수록 AUROC가 올라가고
  full-shot에서 최고값에 도달하는 정상적인 학습 곡선이 4개 코호트 모두에서 나온다.
- **F1 = 0이 거의 사라진다.** 600 run 중 6개 (C2 5개, C3 1개).

### 모델별 full-shot 성능 (5 seed 평균)

| | C1 | C2 | C3 | C4 | 평균순위 |
|---|---|---|---|---|---|
| **AUROC** | | | | | |
| LR | **0.714** | **0.717** | **0.754** | 0.696 | **1.38** |
| XGB | 0.622 | 0.682 | 0.680 | 0.608 | 4.88 |
| MLP | 0.626 | 0.684 | 0.726 | 0.654 | 3.75 |
| RF | 0.706 | 0.715 | 0.741 | 0.667 | 2.38 |
| CAT | 0.675 | 0.705 | 0.750 | **0.708** | 2.62 |
| **AUPRC** | | | | | |
| LR | **0.104** | **0.300** | **0.221** | 0.324 | **1.38** |
| XGB | 0.065 | 0.201 | 0.189 | 0.243 | 4.75 |
| MLP | 0.084 | 0.211 | 0.196 | 0.281 | 3.75 |
| RF | 0.097 | 0.259 | 0.219 | 0.305 | 2.50 |

**LR이 부스팅 계열을 이긴다는 게 이 실험의 핵심 관찰이다.** 표본이 작고 양성이 희소한 구간에서는
트리 앙상블의 표현력이 이득이 되지 않는다. 교수님이 XGBoost만 보라고 하셨을 때
다른 베이스라인도 함께 돌린 이유가 이것이고, 실제로 XGBoost 단독으로는 이 데이터의 난이도를
과대평가하게 된다.

## 5. 과정에서 발견한 이슈

### 5-1. MLP에 클래스 가중치가 빠져 있었다 (수정 완료)
5개 모델 중 MLP만 `BCEWithLogitsLoss()`를 가중치 없이 쓰고 있었다. 극단적 불균형에서
전부 음성으로 수렴해 F1이 전 구간 0이었다 (24칸 중 18칸). `pos_weight=n_neg/n_pos` 추가 후
40칸 중 13칸으로 줄었고, 남은 13칸도 loss 문제가 아니라 test 양성 수 문제다 (12개가 T=12에 몰려 있음).

### 5-2. XGBoost는 k=4에서 학습 자체가 안 된다
8개 데이터셋 전부에서 k=4 AUROC가 정확히 0.500, recall이 정확히 1.000, seed std가 0.000이었다.
원인은 XGBoost 기본값 `min_child_weight=1`이다. p=0.5에서 샘플당 hessian이 0.25라
자식 노드가 1.0을 넘으려면 최소 4개가 필요한데, k=4(2 pos + 2 neg)에서는 어떤 split도 거부된다.
트리가 한 그루도 자라지 않고 예측이 `base_score=0.5`로 고정되며,
`pred = (probs >= 0.5)`이므로 전 샘플이 양성으로 분류된다.
완벽히 분리 가능한 인공 데이터로 검증: n=4, 6은 전부 0.5, n=8부터 정상 학습.

### 5-3. few-shot 샘플러가 소수 클래스에서 shot 수를 못 채운다
`size=min(shot//2, len(cls_indices))` 이므로 train 양성이 부족하면 그만큼만 뽑힌다.
C2 T=12 k=64는 32/32가 아니라 **32 neg / 12 pos, 총 44개**다.
게다가 `replace=True`가 걸려 12명에서 12개를 복원추출하므로
고유 환자가 평균 7.8명만 남는다 (2만 회 시뮬레이션, 이론값 12·(1−(11/12)^12)=7.78).

### 5-4. recall/F1은 이 스케일에서 단독으로 읽으면 안 된다
recall의 분모는 test 양성 수로 고정이다. 따라서 recall이 가질 수 있는 값은 k/P 뿐이다.
원본 json의 recall 1200개를 검산했고 **예외 0건**이다.
C1 T=12는 P=10이라 0.1 단위, C2 T=12는 P=3이라 0.333 단위로만 움직인다.
모든 모델이 동일하게 끊기는 것은 test set의 성질이지 모델의 성질이 아니다.
precision은 분모가 모델마다 달라서 이 현상이 없다 (C1 T=12에서 recall 관측값 11종 vs precision 110종).

### 5-5. full이 few-shot보다 낮은 칸이 있다 (3칸, 전부 부스팅)
240칸 중 full < k64인 칸은 3개뿐이고 LR/MLP/RF에는 하나도 없다.
C4 T=24(Δ=0.036)는 seed std 0.04 안쪽이라 노이즈다.
실질적인 것은 C2 T=12 XGB(0.917 vs 0.704) 하나로, 원인은 부스팅의 불안정성이다.
같은 split의 seed 50에서 LR 0.913 / MLP 0.881 / RF 0.905인데 XGB만 0.359로 무너진다.
full 학습은 양성 12개에 `scale_pos_weight=55.8`이 걸린 상태이고, CV fold당 양성이 2.4개라
하이퍼파라미터 선택이 사실상 난수다. 부스팅만 greedy sequential fitter라 이 조건에 취약하다.
